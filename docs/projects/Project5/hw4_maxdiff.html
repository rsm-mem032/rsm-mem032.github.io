MaxDiff Analysis of MSBA Class Preferences

Counts, MLE, and Bayesian estimation of the MNL model

Author

Mengyao Ma

Published

May 28, 2026

Introduction

When you want to know how much people prefer one thing over another, the instinct is to hand them a rating scale: “rate each class from 1 to 10.” The problem is that humans are terrible at this. Some people cluster everything around 7–8, others spread out, and “an 8” means something different to every respondent. The numbers end up measuring how a person uses a scale as much as what they actually prefer.

MaxDiff — also called Best–Worst Scaling — sidesteps all of that. On each screen of the survey the respondent sees a small subset of items (here, four of the ten classes) and is asked only two questions: which one is the best, and which one is the worst. That’s it. People are genuinely good at picking extremes and making trade-offs, so the data we get back is far more reliable than a rating scale, and it forces real differentiation between items instead of letting everything bunch up in the middle.

In this analysis the ten items are the ten core MSBA classes at UCSD Rady, and the respondents are the students who took the survey (you and your classmates). The goal is to estimate students’ relative preference for each class, and to do it three different ways so we can see what each method buys us:

  1. A simple counts analysis — the percentage of times each class was picked best, minus the percentage of times it was picked worst.
  2. The multinomial logit (MNL) model fit by maximum likelihood, where we write down the log-likelihood and hand it to optim().
  3. The same MNL model fit by Bayesian methods, using a random-walk Metropolis–Hastings sampler we code from scratch.

Here’s what to expect before we even start: the three methods should agree on the broad ranking of classes — if students love a class, all three should say so. Where they differ is in how they quantify the strength of preference and, especially, in how they talk about uncertainty. The counts analysis gives a quick number, the MLE gives a number plus a classical standard error, and the Bayesian version gives a whole distribution we can slice however we like.

Counts Analysis

The counts analysis is the back-of-the-envelope version, and it’s surprisingly informative. For each class \(j\) we ask two questions: of the times it was shown, what fraction did it get picked as best, and what fraction as worst? The difference is a simple score:

\[ \text{score}_j \;=\; \%\text{best}_j \;-\; \%\text{worst}_j \]

A score near \(+1\) means the class is almost always the favorite on screens where it appears; near \(-1\) means it’s almost always the goat; near \(0\) means it’s either middle-of-the-pack or polarizing (picked best by some, worst by others). The nice thing is there’s no model here at all — we’re just counting.

best_n  <- table(factor(d4$item[d4$response ==  1], levels = 1:10))
worst_n <- table(factor(d4$item[d4$response == -1], levels = 1:10))

Bootstrap confidence intervals

A single score is a point estimate; we’d like to know how stable it is. We get that with a bootstrap over respondents: resample the 85 students with replacement, recompute every score, repeat a thousand times, and read off the 2.5th and 97.5th percentiles. Resampling respondents (not individual rows) respects the fact that one student’s answers are correlated with each other.

B <- 1000
resp_ids <- unique(d4$record_id)
id_rows  <- split(seq_len(nrow(d4)), d4$record_id)   # row indices per person

boot <- matrix(NA_real_, B, 10)
for (b in 1:B) {
  samp <- sample(resp_ids, replace = TRUE)
  idx  <- unlist(id_rows[samp])
  db   <- d4[idx, ]
  sh <- as.numeric(table(factor(db$item,                      levels = 1:10)))
  bb <- as.numeric(table(factor(db$item[db$response ==  1],   levels = 1:10)))
  ww <- as.numeric(table(factor(db$item[db$response == -1],   levels = 1:10)))
  boot[b, ] <- bb / sh - ww / sh
}
ci_lo <- apply(boot, 2, quantile, 0.025)
ci_hi <- apply(boot, 2, quantile, 0.975)
plot_df <- data.frame(short = short, score = score,
                      lo = ci_lo, hi = ci_hi)
plot_df$short <- factor(plot_df$short, levels = plot_df$short[order(plot_df$score)])

From MaxDiff Data to MNL Choices

The counts analysis throws away information. When a class is shown but picked neither best nor worst, that’s a signal — it lost to something and beat something — and counts ignores it. The multinomial logit (MNL) model uses all of it, by modeling the choice itself.

The idea: give each class \(j\) a utility \(\beta_j\). On a screen showing items \(\{a,b,c,d\}\), the probability that \(b\) gets picked as best is the soft-max (higher utility ⇒ more likely to be chosen):

\[ P(\text{best} = b) \;=\; \frac{\exp(\beta_b)}{\exp(\beta_a)+\exp(\beta_b)+\exp(\beta_c)+\exp(\beta_d)} \]

Now here’s the clever part of Best–Worst scaling. After picking the best, the respondent picks the worst from the remaining three. Picking the worst is just picking the best on flipped utilities — the item you like least is the one with the lowest \(\beta\), i.e. the highest \(-\beta\):

\[ P(\text{worst} = c \mid \text{best} = b) \;=\; \frac{\exp(-\beta_c)}{\exp(-\beta_a)+\exp(-\beta_c)+\exp(-\beta_d)} \]

So every task gives us two MNL observations: a best-pick from all four, and a worst-pick from the remaining three. With 680 tasks that’s 1360 choice observations feeding the likelihood.

Identifiability. The soft-max doesn’t change if you add the same constant to every \(\beta\) (the constant cancels top and bottom). So only \(J-1 = 9\) of the ten utilities are pinned down. We fix a reference: set \(\beta_1 = 0\) (item 1, 403 AI Math) and estimate \(\beta_2,\dots,\beta_{10}\) relative to it. Everything is read as “utility relative to 403 AI Math.”

We reshape the data into the form the likelihood wants — for each task, the four items shown, which was best, and which was worst — and precompute a few matrices so the likelihood runs fast:

sp <- split(d4, paste(d4$record_id, d4$task))

# n_tasks x 4 matrix of the item numbers shown on each task
IT <- t(sapply(sp, function(z) z$item))
# which item was best / worst on each task
best_item  <- sapply(sp, function(z) z$item[z$response ==  1])
worst_item <- sapply(sp, function(z) z$item[z$response == -1])
# the 3 remaining items per task (full set minus the best pick)
REM <- t(sapply(seq_along(sp), function(t) setdiff(IT[t, ], best_item[t])))

MNL via Maximum Likelihood

Summing the log-probabilities of both picks over every task gives the log-likelihood:

\[ \ell(\boldsymbol{\beta}) \;=\; \sum_{\text{tasks}} \Big[\, \beta_{j^*_b} - \log\!\!\sum_{j \in \text{shown}}\!\! \exp(\beta_j) \;-\; \beta_{j^*_w} - \log\!\!\!\!\sum_{j \in \text{shown}\setminus\{j^*_b\}}\!\!\!\! \exp(-\beta_j) \,\Big] \]

where \(j^*_b\) and \(j^*_w\) are the best and worst picks on that task. The two “\(-\log\sum\exp\)” terms are the soft-max denominators. We compute them with the log-sum-exp trick (max + log(sum(exp(x - max)))) so nothing overflows.

# numerically-stable log-sum-exp, applied to each row of a matrix
row_lse <- function(M) {
  m <- apply(M, 1, max)
  m + log(rowSums(exp(M - m)))
}

# par is length 9 (betas for items 2..10); item 1 is pinned to 0.
loglik <- function(par) {
  beta <- c(0, par)                       # length 10, reference = item 1

  U  <- matrix(beta[IT],  ncol = 4)       # utilities of the 4 shown items
  ll_best  <- beta[best_item]  - row_lse(U)

  UW <- matrix(-beta[REM], ncol = 3)      # FLIPPED utilities of remaining 3
  ll_worst <- (-beta[worst_item]) - row_lse(UW)

  sum(ll_best + ll_worst)
}

We maximize it. optim minimizes by default, so fnscale = -1 tells it to maximize instead, and hessian = TRUE gives us the curvature we need for standard errors.

fit <- optim(par = rep(0, 9), fn = loglik,
             method = "BFGS", hessian = TRUE,
             control = list(fnscale = -1))

beta_hat <- c(0, fit$par)                         # full length-10 vector
# SEs from the inverse of the negative Hessian (observed information)
se_free  <- sqrt(diag(solve(-fit$hessian)))
se_hat   <- c(0, se_free)                          # reference item has SE 0

The raw \(\beta\)’s are on a log-odds scale and hard to read. We convert them into shares of preference, which answer a concrete question — “if all ten classes appeared on one screen, what fraction of the picks would each one get?”:

\[ \hat s_j \;=\; \frac{\exp(\hat\beta_j)}{\sum_{k=1}^{10}\exp(\hat\beta_k)} \]

share_mle <- exp(beta_hat) / sum(exp(beta_hat))

MNL via Bayesian Estimation

The MLE gives us a point estimate and a standard error. The Bayesian version gives us the entire posterior distribution of \(\boldsymbol{\beta}\), which makes uncertainty on derived quantities (like shares) almost free. By Bayes’ rule the posterior is proportional to likelihood times prior:

\[ \pi(\boldsymbol{\beta}\mid \boldsymbol{y}) \;\propto\; L(\boldsymbol{\beta})\cdot \pi(\boldsymbol{\beta}) \]

We use a weakly informative prior, \(\boldsymbol{\beta}\sim N(\mathbf{0},\,10\cdot I)\) — a standard deviation of about \(3.2\) on each coefficient, which is plenty diffuse (it barely nudges the data) without being absurd.

log_post <- function(par) {
  loglik(par) + sum(dnorm(par, mean = 0, sd = sqrt(10), log = TRUE))
}

The sampler

A random-walk Metropolis sampler is about as simple as MCMC gets. From the current \(\boldsymbol{\beta}\), propose a small random jump; if the proposal has higher posterior density, always accept it; if lower, accept it with probability equal to the density ratio. Over many iterations the chain spends time in each region of parameter space in proportion to its posterior probability.

run_mh <- function(start, n_iter, step) {
  K      <- length(start)
  draws  <- matrix(NA_real_, n_iter, K)
  cur    <- start
  lp     <- log_post(cur)
  accept <- 0
  for (t in 1:n_iter) {
    prop  <- cur + rnorm(K, 0, step)        # random-walk proposal
    lp_p  <- log_post(prop)
    if (log(runif(1)) < lp_p - lp) {        # accept/reject on the log scale
      cur <- prop; lp <- lp_p; accept <- accept + 1
    }
    draws[t, ] <- cur
  }
  list(draws = draws, accept_rate = accept / n_iter)
}

Tuning the step size. If the jumps are tiny the chain accepts almost everything but crawls; if they’re huge it almost never accepts and gets stuck. The sweet spot is an acceptance rate of roughly 25–40%. A step of 0.06 lands us right in that band here. (Rule of thumb: too low ⇒ halve the step; too high ⇒ double it.)

n_iter <- 20000
mh <- run_mh(start = rep(0, 9), n_iter = n_iter, step = 0.06)
cat("Acceptance rate:", round(mh$accept_rate, 3), "\n")

Bayes vs. MLE. The posterior means land almost exactly on top of the MLE point estimates, and the posterior standard deviations match the MLE standard errors to two decimals. That’s exactly what theory predicts: with a fair amount of data and a diffuse prior, the likelihood dominates and the two approaches converge. The difference isn’t in the numbers — it’s in what we can do with them. We got 95% intervals on the shares for free, just by pushing each draw through the soft-max and taking quantiles. Getting that from the MLE would require the delta method and some calculus.

Where they agree. Everywhere, basically. All three methods put 495 Marketing Analytics firmly on top and 444 Analytics Consulting firmly at the bottom, and in this dataset the full ranking happens to be identical across methods. Agreement at the extremes is almost guaranteed — a class that’s genuinely loved or hated shows up that way no matter how you slice the data.

Where they could disagree. The risk is always in the middle, where several classes have nearly equal utility (look how the green credible intervals overlap for the middle cluster). There, a handful of flipped picks can reorder ranks, and the three methods might land in different orders. We got lucky with a clean ranking, but those middle ranks are the “soft” ones — don’t over-read a one-spot difference there.

What the MNL adds over counts. It models the choice process explicitly. Every shown item — even one that wasn’t picked — contributes information about not being chosen, which the counts score throws away. The result is estimates on a principled scale (shares that sum to 100%) with proper standard errors.

What Bayes adds over MLE. Uncertainty on derived quantities, for free. Want a credible interval on a share, or on “class A’s share minus class B’s,” or on a market-simulation scenario? Just compute that quantity for every MCMC draw and take quantiles. From the MLE you’d need the delta method for each new quantity.

Discussion

The substantive finding. If you’re a student deciding what to look forward to, the data is loud about one thing: MGTA 495 Marketing Analytics with Yavorsky is the standout favorite — it pulls roughly a quarter of all preference share on its own. Behind it sits a solid tier of well-liked electives (Business Analytics, Customer Analytics, Large Data). The least-loved class is MGTA 444 Analytics Consulting, and the foundational summer course 403 AI Math & Programming also lands low — which probably says more about intensive prerequisite courses being less enjoyable than about the material being bad. Two honest caveats apply throughout: this is a small, self-selected sample of MSBA students, and things like presentation order, prior coursework, and where someone is in the program can all color responses. So read these as this cohort’s vibe, not a universal verdict.

The methodological finding. Each method has its moment:

  • Counts — the quick descriptive read. Perfect for an executive dashboard or a first look; no modeling assumptions, instantly explainable.
  • MLE MNL — rigorous point estimates with classical standard errors. Reach for it when you need a single defensible number to report.
  • Bayesian MNL — when you care about uncertainty on derived quantities (shares, “what if we added a new class?” market simulations, differences between classes), or when you want to extend the model hierarchically to estimate each student’s individual preferences rather than just the group average.

What I’d explore next. The obvious extension is exactly that hierarchical model: a per-respondent set of \(\beta\)’s drawn from a population distribution, which would let us see who loves which class instead of only the average — and would naturally fold the anchoring tasks (item 11) we set aside back into the analysis. I’d also like to bring those anchor screens in properly, since they carry information about whether a class clears an absolute bar, not just how it stacks up against three neighbors.
